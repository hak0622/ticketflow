# 결제 접수 기한 10분 및 경계값 검증

2026-11-17 로컬 검증. 신규 결제 접수 기한을 Booking 생성부터 10분으로 통일했다. 마감 정각부터 신규 접수를 거절한다. 이미 접수·커밋된 PENDING 결제는 기한 이후에도 기존 Saga로 처리한다.

## 구현

- `PaymentDeadlinePolicy`와 시스템 시간대의 Java `Clock`을 사용한다. Saga·Mock은 Booking 잠금 후 검사한다. 기존 멱등 요청 결과는 재사용한다.
- 만료 후보는 생성 시각 이하 조건으로 조회하고, 최종 판정은 잠금 이후 현재 시간으로 수행한다. 기존 cancel 메서드의 non-null expiryThreshold는 만료 경로 식별에 사용하며 후보 조회 시각을 최종 판정에 재사용하지 않는다.
- 미확정·완료 결제 보호, PG 트랜잭션 밖 호출, 최초 승인 선점, 5분 예매 생성 복구, Redis Lua·TTL·재시도·스케줄러 주기는 변경하지 않았다.
- 예매 화면·내 예매 목록과 최신 안내를 10분으로 갱신했다. 기존 데이터에도 새 기준이 적용되므로 10분을 넘긴 미결제 예매는 다음 만료 실행 대상이다.

## 실제 검증

실제 MySQL 8.4·Redis 7 Testcontainers와 별도 로컬 HTTP PG 사용. 고정 시계를 주입하고 DB에 저장된 생성 시각을 기준으로 판정했다. 정책의 1ms 전·정각·후, Saga와 Mock의 1초 전·정각·후를 검사했다. 만료된 신규 요청은 Payment·Outbox·PG 호출·Booking 상태·재고·요청 해시 변경이 없고, 별도 만료 실행에서만 반환됨을 확인했다.

잠금 경합은 별도 트랜잭션이 Booking을 잠그고 `performance_schema.data_lock_waits`에 실제 대기가 발생한 것을 확인한 후 시계를 진행시켰다. Saga·Mock 모두 잠금 획득 후 만료를 판정했다. 관측 권한은 폐기 가능한 테스트 DB에만 부여했다.

접수 후 기한 경과 시험은 테스트 스레드에서 실제 private 준비 메서드를 호출해 PENDING을 커밋하고 latch로 멈췄다. 독립 JDBC 조회로 retryCount=0을 확인한 뒤 마감 이후로 진행시켰다. 만료는 반환을 보류했고, 게이트 해제 후 기존 공개 승인 서비스가 해당 Payment를 재사용하여 승인·확정했다. 전체 Controller 요청 하나를 Aspect로 중단한 시험은 아니다.

승인 응답 유실 후 마감 이후 PG 조회 복구, 기한 후 동일 주문 재사용, 중복 만료의 단일 반환도 확인했다. 신규 클래스는 기존 Saga 테스트 9건을 상속한다. 스케줄러 호출은 명시적 통합 호출이며 실제 자동 60초 실행이나 앱 3대 시험이 아니다.

## 결과와 실패 기록

| 실행 | 결과 |
|---|---|
| 최초 선택 회귀 | 131건 중 129 통과·2 실패 |
| 수정 후 경계·커밋 테스트 | 46건 통과·실패 0 (경계 클래스 21, 커밋 관련 25) |
| 최신 결과 기준 선택 사례 | 131건 모두 통과. 위 두 실행을 합쳐 판정하며 단일 실행 131건 통과로 표현하지 않음 |
| 프론트 | 51건 통과, 수정 화면 Lint·빌드 통과 |
| 전체 프론트 Lint | 기존 무관한 오류 7건 유지 |

최초 잠금 시험은 테스트 사용자에 잠금 관측 권한이 없어 실패했고, 남은 요청 스레드가 다음 fixture 정리에 영향을 주어 두 번째 실패가 발생했다. 테스트 전용 관측 권한과 executor 종료 보장을 추가했다. 추가로 신규 요청 생성 헬퍼의 컴파일 오류를 수정했으며 최초 로그도 보존했다. 운영 기대값이나 timeout은 완화하지 않았다.

최종 경계 클래스의 21개 사례별 DB·Redis 스냅샷과 PG 호출 수를 저장했다. 재고가 있는 20개 스냅샷은 fixture의 전체 수량 3과 비교했다. 진행 중 요청은 요청별 기록으로 구분하며, 안정된 상태에서만 `잔여 + 취소되지 않은 Booking = 전체`를 판정했다. 기존 Lua 부분 쓰기 회귀 15건은 추가 손상 방지를 검사하며 자동 재고 복구로 표현하지 않는다.

## 재현과 한계

```bash
./gradlew test --offline --tests studying.blog.fault.PaymentDeadlineIntegrationTest
```

Docker Desktop·Java 17·Gradle 의존성이 필요하다. 신규 테스트의 MySQL·Redis는 폐기 가능한 Testcontainers 대상이다. H2 회귀에 사용한 localhost:6379 Redis는 별도 테스트 컨테이너이며 개발 Redis 6380은 변경하지 않았다.

원본은 Git 제외 `test-results/payment-expiry-boundary/` 아래 실행 디렉터리의 로그·XML·스냅샷·해시·명령 기록이다. 공개 저장소에는 원본 PG 기록이 포함되지 않는다. 전체 테스트 저장소 검증, 실제 Toss, 실제 10분 대기, 자동 스케줄러 주기·성능·재배포는 미실행이다. 10분은 신규 접수 기한이며 60초 스케줄러와 결제 확인 지연을 포함한 반환 완료 SLA가 아니다.
